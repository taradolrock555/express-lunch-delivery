# ระบบจัดเส้นทางและแบ่งงานไรเดอร์ (ข้าวกล่องเดลิเวอรี ส่งด่วนมือเที่ยง)

โปรเจกต์นี้เป็นระบบต้นแบบสำหรับร้านข้าวกล่องที่ต้องส่งอาหารให้ลูกค้า 20–30 ออเดอร์ภายในเวลา
11:30–12:30 น. โดยมีหน้าจอสำหรับเจ้าของร้านและหน้าจอสำหรับไรเดอร์ แยกส่วนหน้าเป็น
Angular และส่วนหลังเป็น Node.js Web API ที่เขียนด้วย TypeScript + Express + SQLite

> โปรเจกต์นี้พัฒนาตามโจทย์รายวิชา **NodeJS Web API (TS)** และแทนที่ฐานข้อมูล Firebase
> Firestore เดิมด้วย SQLite เพื่อให้รันได้ในเครื่องโดยไม่ต้องใช้บัญชีคลาวด์

## ฟีเจอร์หลัก

### หน้าจอเจ้าของร้าน

- เพิ่ม/แก้ไข/ลบข้อมูลลูกค้า พร้อมเบอร์โทร ที่อยู่ และพิกัดบนแผนที่
- เพิ่ม/แก้ไข/ลบออเดอร์ จำกัด 1–3 กล่องต่อออเดอร์
- ระบบแบ่งออเดอร์ให้ไรเดอร์อัตโนมัติตามต้นทุน; เจ้าของเลือกไรเดอร์เองเพื่อ override รายออเดอร์ได้
- จำกัดไม่เกิน 3 ออเดอร์ที่ยังไม่เสร็จต่อไรเดอร์
- ลูกค้า 1 คนมีออเดอร์ที่ยังไม่เสร็จได้ครั้งละ 1 ออเดอร์ ต้องรอให้จัดส่งเสร็จหรือยกเลิกก่อนสั่งรอบใหม่
- เปลี่ยนสถานะออเดอร์: รอดำเนินการ, กำลังเตรียม, พร้อมจัดส่ง, กำลังจัดส่ง, จัดส่งแล้ว, ยกเลิก
- วางแผนการแบ่งงานและลำดับจุดส่งให้ค่าส่งรวมต่ำ พร้อมรักษาไรเดอร์ที่เจ้าของกำหนดเอง
- แผนที่ขนาดใหญ่แสดงเส้นทางแยกสีตามไรเดอร์ สูงสุด 10 สี
- สรุปจำนวนกล่อง ระยะทาง เวลาเดินทาง ค่าส่ง กำไร/ขาดทุน และเปรียบเทียบกับงบประมาณ
- ปุ่มคำนวณใหม่ เลือกวิธีวางแผน และเผยแพร่แผนให้ไรเดอร์
- แจ้งเตือนเมื่อค่าส่งเกินงบ กำไรต่ำกว่าเป้า หรือมีเส้นทางที่คาดว่าจะไปถึงหลัง 12:30 น.

### หน้าจอไรเดอร์

- กรอกรหัสพนักงาน (ตัวอย่าง `JOB-001` ถึง `JOB-010`) เพื่อดูงานของตัวเอง
- แสดงจำนวนกล่อง จำนวนจุดส่ง ระยะทาง และเวลาถึงโดยประมาณ
- แสดงลำดับจุดส่ง เช่น `จุดที่ 1 ... → จุดที่ 2 ...`
- ปุ่มเปิดเส้นทางใน Google Maps, ปุ่มนำทางรายจุด และปุ่มโทรหาลูกค้า
- เตือนเมื่อแผนที่เผยแพร่ไม่ใช่แผนของวันนี้

## เตรียม deploy เพื่อส่งงาน

- แนะนำใช้ repository เดียว (monorepo) ที่ root ของ V2; ใส่ URL นี้ใน `Git repository URL 1`
  และเว้น URL 2 ว่าง ถ้าไม่ได้แยก Front-end/Back-end เป็นคนละ repository
- ถ้า deploy Front-end และ Back-end แยก URL ให้ตั้ง `frontend/public/app-config.js`
  เป็น backend URL ที่ลงท้าย `/api` และตั้ง `CORS_ORIGIN` ใน backend เป็น origin ของ Front-end
- ตั้ง `SQLITE_FILE` ให้อยู่บน persistent disk/volume ของผู้ให้บริการก่อน deploy
- API ยังไม่มี login ตามขอบเขต V2 ที่ตกลงกัน; ใช้เฉพาะข้อมูล seed/fake และอย่าเปิดเผยข้อมูลลูกค้าจริง
- ต้องกรอก Front-end URL และ Back-end URL เป็น HTTPS URL ที่ deploy แล้ว ไม่ใช่ `localhost`

`npm start` ตั้งค่าให้ frontend รับการเชื่อมต่อจากเครื่องอื่นในวงเดียวกันด้วย
และ `frontend/src/app/services/api.config.ts` จะเรียก API ตาม hostname ของหน้าเว็บอัตโนมัติ
เช่น เปิดจาก `http://192.168.3.182:4200` จะเรียก `http://192.168.3.182:3000/api`

### เปิดจากเครื่องอื่นในวง Wi-Fi เดียวกัน

1. หา IPv4 ของเครื่องที่รันโปรเจกต์:

```powershell
ipconfig
```

หรือ

```powershell
Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object { $_.IPAddress -notlike '127.*' -and $_.IPAddress -notlike '169.254.*' } |
  Select-Object InterfaceAlias, IPAddress
```

2. เปิดจากเครื่องอื่น:

```text
http://<IPv4-ของเครื่องที่รัน>:4200
```

ตัวอย่าง: `http://192.168.3.182:4200`

3. หากเปิดไม่ได้ ให้ตรวจว่า Windows Firewall อนุญาต `Node.js JavaScript Runtime`
   สำหรับพอร์ต 3000 และ 4200 (เลือก Allow เมื่อมีหน้าต่างถาม)
   และทั้งสองเครื่องต้องต่อ Wi-Fi/เครือข่ายเดียวกัน

> การเปิดจากอินเทอร์เน็ตภายนอกต้อง deploy หรือใช้ tunnel เช่น Cloudflare Tunnel,
> ngrok หรือ reverse proxy ไม่ใช่แค่เปิดพอร์ตในเครื่อง

| --- | --- |
| `JOB-001` … `JOB-010` | ดูใบงานของไรเดอร์หลังกดเผยแพร่แผน |

และออเดอร์รอดำเนินการ 2 รายการ ออเดอร์เริ่มต้นใช้การจัดไรเดอร์อัตโนมัติ

## เงื่อนไขทางธุรกิจที่ระบบบังคับใช้

- 1 ออเดอร์มีได้ 1–3 กล่อง
- 1 ไรเดอร์รับได้ไม่เกิน 3 ออเดอร์ที่ยังไม่เสร็จ
- ลูกค้า 1 คนมีออเดอร์ที่ยังไม่เสร็จได้ครั้งละ 1 ออเดอร์
- ลูกค้าต้องอยู่ในรัศมีเส้นตรงไม่เกิน 3 กิโลเมตรจากร้าน
- ออกเดินทาง 11:30 น. และต้องถึงลูกค้าไม่เกิน 12:30 น. (1 ชั่วโมง)
- ไรเดอร์ขับ 30 กม./ชม.
- ราคาขาย 65 บาท/กล่อง
- ต้นทุนอาหาร 40 บาท/กล่อง
- ค่าส่ง 15 บาท/เที่ยว + 2 บาท/กม./กล่อง
- กำไรสุทธิ = รายได้ − ต้นทุนอาหาร − ค่าส่ง

ค่าส่งของแต่ละเที่ยวคำนวณจาก:

```text
ค่าส่ง = 15 + (ระยะทางกิโลเมตร × 2 × จำนวนกล่องในเที่ยว)
```

## API หลัก

| Method | Endpoint | คำอธิบาย |
| --- | --- | --- |
| GET | `/api/health` | ตรวจสอบสถานะเซิร์ฟเวอร์ |
| GET | `/api/config` | ข้อมูลร้านและราคา |
| GET/POST | `/api/customers` | ดู/เพิ่มลูกค้า |
| PUT/DELETE | `/api/customers/:id` | แก้ไข/ลบลูกค้า |
| GET/POST | `/api/orders` | ดู/เพิ่มออเดอร์ |
| PUT/DELETE | `/api/orders/:id` | แก้ไข/ลบออเดอร์ |
| POST | `/api/routes/preview` | คำนวณแผนแต่ยังไม่บันทึก |
| POST | `/api/routes/publish` | คำนวณและบันทึกแผนล่าสุด |
| GET | `/api/routes/current` | ดูแผนที่เผยแพร่ล่าสุด |
| GET | `/api/riders` | ดูรายชื่อไรเดอร์ |
| GET | `/api/riders/tasks/:jobCode` | ดูใบงานของไรเดอร์ |
| POST | `/api/geo/route` | คำนวณเส้นทางระหว่างพิกัด |

ตัวอย่างการคำนวณแผน:

```json
POST /api/routes/preview
{
  "strategy": "alternative"
}
```

- `alternative` = แผนประหยัดต้นทุน (จัดกลุ่มและเรียงจุดส่งให้ค่าส่งรวมต่ำที่สุด)
- `nearest` = แผนเปรียบเทียบที่เรียงจุดใกล้ร้านก่อน

รายละเอียด request/response ทั้งหมดอยู่ใน [`backend/README.md`](backend/README.md)

## การทำงานของตัวจัดเส้นทาง

1. ดึงออเดอร์ที่มีสถานะ `ready` หรือ `delivering` และรายชื่อไรเดอร์ที่พร้อม
2. ล็อกไรเดอร์ของออเดอร์ที่เจ้าของกำหนดเองหรือกำลังจัดส่ง
3. ขอระยะทางถนนจาก OSRM (ถ้าไม่ได้จะใช้ Haversine)
4. ใช้ตัวจัดกลุ่มแบบ local search แบ่งออเดอร์ที่เหลือให้ไรเดอร์ โดยไม่เกิน 3 ออเดอร์ต่อคน
5. หาลำดับจุดส่งที่ค่าส่งต่ำภายในแต่ละเที่ยว โดยคิดค่าเที่ยวและจำนวนกล่อง
6. ตรวจเวลาเดินทางของทุกเที่ยวว่าถึงก่อน 12:30 น.
7. สรุปต้นทุน กำไร และเปรียบเทียบกับงบประมาณ

ระบบเป็น heuristic สำหรับงานประมาณ 20–30 ออเดอร์ จึงเร็วและเหมาะกับ demo
แต่ไม่ได้ยืนยันว่าเป็นคำตอบที่ดีที่สุดในเชิงคณิตศาสตร์สำหรับทุกกรณี

## หมายเหตุ

- SQLite เก็บไฟล์ที่ `backend/data/lunch-delivery.db` (ถูก ignore ใน Git)
- ถ้าใช้ OSRM ไม่ได้ ระบบยังทำงานได้ด้วยระยะเส้นตรง แต่ระยะทางและค่าส่งจะหยาบขึ้น
- แผนที่ใช้ OpenStreetMap ต้องมีอินเทอร์เน็ต
- การแก้ไขลูกค้า/ออเดอร์จะล้างแผนที่เผยแพร่ล่าสุด เพื่อไม่ให้ไรเดอร์เห็นแผนเก่าที่ไม่ตรงกับข้อมูล
- อย่า commit ไฟล์ `.env` หรือฐานข้อมูลจริง
- API และหน้าไรเดอร์ยังไม่มีการยืนยันตัวตน และ API เปิด CORS; ใช้เฉพาะเครื่อง/เครือข่ายส่วนตัวที่เชื่อถือได้
  อย่าเปิดสู่อินเทอร์เน็ตหรือใช้กับข้อมูลลูกค้าจริงจนกว่าจะเพิ่มระบบล็อกอิน

## การแก้ปัญหาที่พบบ่อย

**Backend เปิดไม่ขึ้น / `node:sqlite` ไม่พบ**

- ตรวจ `node -v` ต้องเป็น 22.22.3 ขึ้นไป หรือ 24.15 ขึ้นไป เพื่อให้ Angular 22 และ `node:sqlite` ทำงานได้

**Frontend เรียก API ไม่ได้**

- ตรวจว่า backend รันที่พอร์ต 3000
- ตรวจ `frontend/src/app/services/api.config.ts`
- เปิด `http://localhost:3000/api/health` ในเบราว์เซอร์

**แผนที่ไม่แสดง**

- ตรวจการเชื่อมต่ออินเทอร์เน็ต (OpenStreetMap)
- เปิด Developer Tools ดู error ของ Leaflet

**ไรเดอร์ค้นหารหัสไม่เจอ**

- ต้องกด “เผยแพร่แผนให้ไรเดอร์” ก่อน
- ตรวจรหัส เช่น `JOB-001`
- หากแก้ข้อมูลหลังเผยแพร่ ต้องเผยแพร่แผนใหม่
